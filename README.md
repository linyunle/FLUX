# FLUX

<img src="assets/logo.png" width="96" alt="FLUX">

FLUX —— 给 nikki(mihomo)用的流量面板:按 **设备 / 机场 / 节点 / 策略组 / 规则 / 访问目标** 统计流量,看小时、天趋势。
数据只存在你自己的路由器上(SQLite),不联网上报。

## 功能
- 设备:点开设备列表里的一台,看这台设备的详情(趋势、直连/代理占比、访问目标、用到的节点、策略组、规则);在概览筛选某台设备时自动隐藏与它无关的全局内容;顶部统计栏滚动时固定;同一台设备的 IPv4 / 多个 IPv6 按 MAC 合并;可改名,可粘贴 `uci show dhcp` 批量导入名字;顶部可多选筛选设备
- 实时:每 2 秒刷新,直连 / 代理速度分开统计,另有连接数;左侧栏常驻四张实时小卡(总速度、直连、代理、连接数);概览里「实时速度 / 直连速度 / 代理速度 / 最活跃设备 / 最活跃节点」都是独立卡片
- 概览卡片可自由排列:「设置 → 外观 → 概览卡片」里每张卡片单独设宽度(1/4 ~ 整行)、图表高度、显示/隐藏、顺序,同一行放得下的卡片自动并排
- 设备流量消耗 Top(概览卡片,可切 全部/代理/直连,点一行看该设备访问的域名);访问目标 Top 和域名清单点一行看是哪些设备访问的;节点页点一个节点进入详情(连接的设备、域名、策略组、规则、趋势);搜索访问目标时概览只留统计卡片和访问目标 Top
- 外观:侧栏每个内容(实时卡片、连接状态、设备筛选、主题切换、版本号)可单独显示/隐藏,侧栏可收起成窄条;卡片阴影和透明度可调
- 趋势:堆叠柱 / 分组柱 / 折线 / 面积四种样式,可单独设上行、下行颜色,可把上行和下行拆成两张图;24 小时 / 48 小时 / 7 天(按小时)、14 / 30 天(按天),带表格视图
- 域名清单:谁访问过哪些域名、走直连还是代理、最近哪天,可合并子域名,可导出 CSV(按连接记录统计,不是 DNS 查询日志)
- 规则与策略组:点一行就能钻取,并显示每个策略组/规则实际走了哪些节点
- 机场与节点:按节点名自动归类机场(取「机场名 | 地区 01」里竖线前面的部分,也可以写规则),看每个机场/节点的下行、上行、合计和趋势;顶部可按机场筛选,概览、设备、域名都会跟着只看这个机场;时间范围有「本月」
- 界面:左侧栏导航(概览/机场/节点/设备/域名/规则策略/设置),小卡片布局;「设置 → 外观」可切换 6 套预设主题、跟随系统/浅色/深色、自定义强调色和上下行颜色、紧凑/标准/宽松密度、页面宽度、圆角、字号,概览卡片可隐藏和调序;只保存在当前浏览器
- 应用识别 / Top Talkers:按域名(SNI)特征库 + 端口把流量归到具体应用和类别(流媒体、网盘、P2P、代理隧道等),点一行看是哪些设备在用;「设置 → 应用识别」可加自定义规则。这不是真正的深度包检测(面板只能读到 nikki 接口,看不到加密内容)
- 流量堆叠趋势:按小时的堆叠面积图,可按 设备 / 节点 / 去向 / 应用 / 类别 / 协议 堆叠,悬停看每个系列的值,标出峰值
- 网络质量 QoE:节点延迟 / 抖动 / 超时率(来自 nikki 测速)、路由器 TCP 重传率(内核全局计数)、出口隧道协议分布;不提供应用层丢包率和分设备 RTT(数据拿不到)
- 访问密码 / 隐私模式:「设置 → 安全与隐私」可设置登录密码(加盐哈希,输错 5 次锁 1 分钟),也可用环境变量 PANEL_PASSWORD;隐私模式把域名 / 目标 IP 模糊显示,悬停才显示
- 视图预设:概览顶部一键切换 全部 / 总览 / 排障 / 安全 四组卡片;顶部筛选条的标签可逐个取消,也可「清除全部」
- 告警与推送:内置 6 类规则(新设备入网、流量突增、节点故障/恢复、TCP 重传率偏高、连接数异常、nikki 失联),触发后记录在「告警」页签和概览「最近告警」卡片,并可推送到 Bark / Telegram / 企业微信 / 飞书 / ntfy / 通用 Webhook;支持静默时段、同一对象的冷却间隔;流量突增按「设备 × 钟点」的历史均值做基线(样本不够时用近 24 小时中位数)。推送密钥只存在 data 目录的数据库里,页面不回显。环境变量 ALERT_EVAL_SEC(检查间隔,默认 30)、ALERT_LEARN_SEC(新设备学习期,默认 900)
- 安全页(v0.11):接入 AdGuard Home(只读,账号密码在「设置 → DNS」里填,只存 data 目录)看 DNS 查询 / 拦截统计和最近被拦截的查询;分流检查(国内站点走了代理 / 境外站点直连 / 走代理却本地解析,启发式);目的地国家 / ASN(需要 GeoIP 库,可在「设置 → 目的地数据库」一键下载(GitHub 上的 GeoLite2 镜像,失败再试 DB-IP Lite;路由器直连不通时可在同一页设置 HTTP 下载代理));活跃时段热力图;数据质量自检
- 安全页顶部有指标卡和「需要关注」清单(采集、告警、节点、DNS、分流、兜底规则、套餐、面板保护),点一项直达对应页面
- 规则健康(规则策略页):从未命中的规则、流量最多的规则、落到兜底 Match 的占比
- 机场套餐:设置月流量和重置日,估算用量、预计用完日,到阈值触发告警;周报:汇总 7 天并可每周自动推送
- Prometheus:`/metrics` 文本指标;环境变量 `METRICS_TOKEN` 可让 Prometheus 用口令抓取(`Authorization: Bearer` 或 `?t=`)
- 连接设置:在网页里填 nikki API 地址和密码,保存前会先验证
- 新版本提示:查 GitHub Release,更新只需一条命令

## 部署(路由器上)
```sh
mkdir -p /mnt/data/docker/flux && cd /mnt/data/docker/flux
# 放入 docker-compose.yml和 .env(可选)
docker compose up -d
```
打开 `http://路由器IP:8099/`,右上角「连接设置」填 nikki API(同机一般是 `http://127.0.0.1:9090`)和密码。

## 更新
```sh
cd /mnt/data/docker/flux && docker compose pull && docker compose up -d
```
数据在 `./data`,更新不丢。旧版 v1 的数据库会自动升级。

## 发布新版本(开发者)
推一个 `v*` 标签,GitHub Actions 会构建 amd64 + arm64 镜像并推到 `ghcr.io/<owner>/flux`,同时创建 Release。
首次发布后,到仓库 Packages 页面把该包设为 Public,路由器才能免登录拉取。

## 设备主机名
容器会只读挂载路由器的 `/tmp/dhcp.leases`,动态分配地址的设备如果上报了主机名会自动显示;静态表可在页面里「设备 → 导入设备名」粘贴 `uci show dhcp` 批量导入。

## 精度说明
- 每 10 秒采样一次 `/connections`,短于一个周期的连接看不到,连接关闭前最后一个周期的字节会丢
- 不经过 nikki 的流量(绕过大陆 IP、局域网内互访、路由器自身)统计不到;设置 `WAN_IFACE` 可在页面看到 WAN 实际总量对账

- 目的地国家只对「能看到真实目的地」的连接有效(直连、非 fake-ip);经代理的流量只能看到节点所在国家
- 分流检查用内置的常见域名清单,只是排查线索

## 设备上线 / 离线提醒(v0.18.0)
- 设备页每台设备显示在线/离线和最后在线时间,点「🔔 关注」后,它的上线/离线会记进告警时间线并按规则推送。

## 诊断包、宽带质量、订阅异常(v0.19.0)
- 设置 → 访问与日志:「自检」列出面板自己的异常(连不上 nikki、后台线程退出、数据库/磁盘、日志里重复报错、页面脚本报错、流量归不到机场、套餐名对不上等);「下载诊断包」默认打码 IP/MAC/设备名,不含密码/Token。
- 页面脚本报错(含卡片渲染失败)自动回传到面板日志,自检和诊断包里能看到。
- 宽带质量:每 30 秒对默认网关和公共 DNS(223.5.5.5、114.114.114.114)发 ICMP(无权限时退回 TCP 53),记录延迟/丢包(wanq 表,按小时汇总);路由器状态卡多一格「宽带」;记录 WAN 掉线/恢复和 WAN 口 IP 变化。新规则 wan_down / wan_ip / wan_loss。
- 订阅超过 N 小时(默认 48)没更新提醒(规则 sub_stale)。

## v0.19.1(根据第一份真实诊断包修的问题)
- 订阅(provider)里的节点不在 nikki 的 /proxies 里,以前只读到本地配置的几个节点,所以节点评分/网络质量只有「备用节点」。现在额外读 /providers/proxies,订阅节点的测速记录也进评分。
- 节点测速对订阅里的节点改用 /providers/proxies/<订阅>/<节点>/healthcheck(旧接口 404 时才退回 /proxies/<节点>/delay),并在日志/设置页里显示失败原因。
- 宽带丢包:不回应 ICMP 的目标(从没通过)不再参与;所有正常回应的目标都丢包才提醒;默认阈值 30%→50%。
- 路由器自己的地址(v4/v6)显示为「路由器本机」,且不再触发「新设备」;查不到 MAC 的 IPv6 临时地址也不再当新设备。

## 路由器日志、UPS、证书/域名到期、全部磁盘(v0.20.0)
- **路由器系统日志**(设置 → 路由器日志,默认关闭):路由器通过 UDP 把日志转发给面板(路由器上只改一条 `log_ip` 设置,设置页里有现成命令),面板存进自己的 SQLite,按保留天数(默认 7 天)和最大条数(默认 10 万)每小时自动清理,所以不增加路由器闪存/硬盘的写入。只收内网来源,每秒最多入库 300 条;UDP 会丢包、容器停止期间收不到。可按级别/关键词查看。出现严重级别或内存不足/文件系统错误/内核崩溃等日志时告警(规则 syslog_crit)。
- **UPS(NUT)**(设置 → UPS 与到期,默认关闭):只读连 upsd(默认 127.0.0.1:3493,名称默认 CyberPower),读电量/负载/续航/市电状态,不需要 NUT 账号密码、不发控制命令。断电/恢复、电量低、电池需更换、读不到 UPS 会告警(规则 ups_onbatt / ups_low / ups_lost);状态卡多一格 UPS。
- **证书/域名到期**:填名单(证书 host[:端口]、域名),每 6 小时检查;证书连过去读到期日(自签名也能读,同时标记是否受信任),域名走公共 RDAP(不是所有后缀支持)。规则 cert_expire(默认提前 14 天)/ domain_expire(默认 30 天)。
- **全部磁盘空间**:路由器状态卡的磁盘格显示最满的一块,设置页列出所有;告警按每块盘分别判断。容器里默认只看得到自己的数据盘,看路由器别的硬盘要在 compose 里加只读挂载 `- /mnt:/host/mnt:ro,rslave`(或设环境变量 `DISK_PATHS=名称=路径`)。
- 备份包含日志/UPS/到期名单设置;诊断包包含这几项的状态(不含日志内容)。
